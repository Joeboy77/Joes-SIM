Memory is slow compared with the processor. A **cache** is a small, fast memory between them that
keeps copies of the mailboxes the program is using now. If the value is in the cache it is a
**hit** (fast); if not it is a **miss**, and a whole **block** of mailboxes is fetched from memory.

Programs tend to reuse the same mailboxes (**temporal locality**: a loop counter) and to use
neighbouring ones (**spatial locality**: a table), so a small cache catches most accesses.

## Where does a block go?

The cache is divided into **sets**. An address, written in binary, splits into three parts:

- the **offset**: which mailbox inside the block;
- the **index**: which set the block must go in;
- the **tag**: the rest, kept to tell apart the blocks that share a set.

A **direct-mapped** cache has one place (way) per set. A **set-associative** cache has several, and
a **fully associative** cache has a single set where any block can go. When a set is full, the
**replacement policy** (LRU, FIFO or random) picks which block to throw out.

## Kinds of miss

- **Compulsory**: the first time a block is used. No cache can avoid these.
- **Capacity**: the cache is too small for everything the program is using.
- **Conflict**: there was room, but the block's set was full. More ways help.

**Writes** need a policy too: **write-back** marks a block dirty and writes it to memory only when
it is thrown out; **write-through** writes every change to memory straight away.
